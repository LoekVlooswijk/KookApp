Kookapp — Technisch Plan v2

React Native (Expo) · SQLite · Claude API · Nextcloud sync
Ontwerpprincipes
Privacy-first & lokaal. Alle data staat in SQLite op het device. Geen account, geen externe database. Claude API-calls bevatten alleen het recept waar de gebruiker op dat moment mee werkt — nooit de hele collectie.
Offline-kookmodus. De receptweergave, checkboxes, timers en schaling werken volledig zonder internet. AI-features (tips, chat, extractie) zijn gracefully disabled met een duidelijke melding als er geen verbinding is.
Eén gebruiker, geen sync-conflicten. Export/import via JSON naar Nextcloud (WebDAV) is een bewuste backup-actie, geen real-time sync. Simpel en voorspelbaar.
Tech stack
React Native (Expo) expo-sqlite expo-secure-store Claude API (Haiku default) JSON export → Nextcloud WebDAV
API-key opslag: Sla de Claude API-key op via expo-secure-store (Keychain op iOS, Keystore op Android). De key wordt bij eerste gebruik ingevoerd door de gebruiker in een instellingenscherm. Hardcode nooit een key. Overweeg later een lichte proxy (Cloudflare Worker) zodat de key helemaal niet op het device staat.
Model-keuze per feature: Gebruik claude-haiku-4-5 als default voor alle AI-features (extractie, tips, receptaanpassingen). Alleen voor complexere taken zoals weekplanning met constraints of chat-interacties kan claude-sonnet-4 worden aangesproken. Maak dit configureerbaar in de instellingen.
Eenheden-normalisatie
Ingrediënten worden bij invoer (handmatig of via Claude-extractie) genormaliseerd naar een vaste set eenheden. Dit is noodzakelijk voor het schalen van porties en aggregeren van boodschappenlijsten.
Canonieke eenheden
Gewicht:    g, kg
Volume:     ml, l, el (eetlepel), tl (theelepel)
Stuks:      stuk(s), teen, plak, tak, blad
Vrij:       snuf, naar smaak
Claude krijgt bij elke extractie-prompt de instructie om ingrediënten te normaliseren naar deze eenheden. Bekende synoniemen (bijv. "eetlepels" → "el", "theelepels" → "tl", "gram" → "g") worden ook client-side afgevangen met een mapping-tabel als fallback.

Functies — bouwvolgorde
1
Recepten handmatig invoeren + scrollbare kookweergave
Formulier met ingrediënt-groepen, stapsecties, timers per stap, tags, categorie, favorieten, wil-ik-proberen. Kookweergave met checkboxes (ingrediënten + stappen), timers, en wake-lock zodat het scherm niet uitgaat. Dit valideert het volledige datamodel met echte data voordat AI-extractie wordt gebouwd.
1b
Receptlijsten / thema-verzamelingen
Handmatige lijsten (bijv. «Zomerrecepten», «Uitgebreid koken»): op de receptenpagina horizontale thema-boxen (inclusief «Nieuwe lijst»); tik op een box om recepten in die lijst te zien. Recepten toevoegen/verwijderen per lijst vanuit die weergave. Op het receptdetail: aan/uit per lijst. Eén recept kan in meerdere lijsten staan. Geen AI; volledig offline.
2
Porties instellen → ingrediënten schalen
Puur rekenkundig, geen AI. Slider of ±knoppen. Respecteert eenheden-normalisatie (bijv. 1000ml → 1l). "naar smaak" en "snuf" worden niet geschaald.
3
Zoeken + filteren in eigen receptenverzameling
Full-text search op titel, ingrediënten, tags. Filters op categorie, favoriet, bereidingstijd, wil-ik-proberen, en (optioneel) lidmaatschap van een receptlijst.
4
Instellingenscherm + API-key opslag
API-key invoer via secure store. Model-keuze (Haiku/Sonnet). Eenheden-voorkeuren. Dit moet staan vóór de eerste AI-feature.
5
URL plakken → recept extraherenHaiku
Fetch de pagina-HTML, stuur naar Claude met structured output (JSON). Valideer response client-side tegen het schema. Toon preview vóór opslaan zodat de gebruiker kan corrigeren. Fallback-UI bij parse-fouten.
6
Tips & chat tijdens het kokenHaiku
Eén component dat begint als een tips-knop (snelle one-shot vragen over het huidige recept) en uitklapt tot een mini-chatvenster. Context = huidig recept + aantal personen. Microfoon-knop alvast zichtbaar maar disabled. Zo hoeft dit later niet opnieuw gebouwd te worden.
7
Notities → Claude past recept aan + versiegeschiedenisHaiku
Gebruiker typt een notitie ("volgende keer meer knoflook", "30 min was te lang"). Claude ontvangt het huidige recept + notitie en retourneert een aangepaste versie. Oude versie wordt opgeslagen als snapshot in recipe_versions. Terugzetten van een eerdere snapshot naar het actieve recept staat in het stappenplan onder «later» (zie onderaan deze lijst): UI op receptdetail, FullRecipe uit JSON terugschrijven, optioneel huidige staat weer als nieuwe versie vastleggen vóór restore.
8
Weekplanner + boodschappenlijstSonnet
Dagen selecteren, recepten toewijzen (handmatig of AI-suggestie). Eén of meerdere dagen koken. Wensen-tekstvak voor AI ("licht deze week", "iets met aubergine"). Boodschappenlijst wordt geaggregeerd uit geplande recepten: zelfde ingrediënt + eenheid → optellen. Gegroepeerd op categorie (groente, zuivel, droog, etc.). Checkboxes per item.
9
Technieken-bibliotheekHaiku
Doorzoekbare lijst met koktechnieken. Claude kan technieken genereren of uitleggen. Link naar recepten die de techniek gebruiken.
10
Recepten zoeken via internetSonnet + web search
Gebruiker beschrijft wat ze willen, Claude zoekt online en presenteert opties. Geselecteerd recept wordt geëxtraheerd en opgeslagen via dezelfde flow als feature 5.

Claude API — prompt specs per feature
Feature 5 — URL → recept extractie
System prompt:
Je bent een recept-parser. Extraheer het recept uit de volgende HTML 
en retourneer ALLEEN valid JSON in het opgegeven schema. 
Normaliseer eenheden: gebruik g, kg, ml, l, el, tl, stuk(s), teen, 
plak, tak, blad, snuf, "naar smaak". 
Groepeer ingrediënten als het origineel secties heeft.
Schat prep_time_min, cook_time_min, total_time_min als ze niet 
expliciet vermeld staan.

Output schema:
{
  "title": string,
  "description": string | null,
  "base_servings": number,
  "prep_time_min": number | null,
  "cook_time_min": number | null,
  "total_time_min": number | null,
  "category": string | null,
  "ingredient_groups": [
    {
      "title": string | null,
      "ingredients": [
        { "name": string, "amount": number | null, "unit": string | null }
      ]
    }
  ],
  "step_sections": [
    {
      "title": string | null,
      "steps": [
        { "description": string, "timer_seconds": number | null }
      ]
    }
  ],
  "tags": [string]
}

Validatie client-side:
- Check of JSON valid is
- Check of title niet leeg is
- Check of minstens 1 ingrediënt en 1 stap aanwezig zijn
- Bij falen: toon foutmelding + raw response voor debugging
Feature 6 — Tips & chat context
System prompt:
Je bent een ervaren kok die helpt tijdens het koken. 
Je hebt context over het recept dat de gebruiker aan het maken is.
Geef korte, praktische antwoorden. Maximaal 2-3 zinnen tenzij
de gebruiker expliciet om meer detail vraagt.
Antwoord in het Nederlands.

User message bevat:
- Het volledige recept (titel, ingrediënten, stappen)
- Aantal personen waarvoor wordt gekookt
- De vraag van de gebruiker
Feature 7 — Recept aanpassen o.b.v. notitie
System prompt:
De gebruiker heeft een notitie geschreven over een recept. 
Pas het recept aan op basis van de notitie.
Retourneer het VOLLEDIGE aangepaste recept in hetzelfde JSON-schema 
als de extractie-feature. Wijzig ALLEEN wat de notitie impliceert.

User message bevat:
- Het huidige recept als JSON
- De notitie van de gebruiker
Later — versie terugzetten (geen Claude)
Implementatie-stappen (stappenplan):
1. repo: listRecipeVersions(recipe_id) → id, version_number, note, created_at (snapshot alleen bij restore laden).
2. receptdetail: sectie «Eerdere versies» met FlatList / modal; knop «Bekijk» toont read-only samenvatting (titel + aantallen).
3. «Terugzetten»: Alert bevestigen; optioneel checkbox «Huidige versie eerst bewaren» (nieuwe recipe_versions-rij met note "Vóór terugzetten").
4. snapshot JSON → FullRecipe valideren (zelfde velden als getFullRecipe); bij fout: geen write.
5. applyRestoredRecipe(recipeId, fullRecipe) — transactie: DELETE/INSERT nested zoals updateRecipe, of hergebruik applyRecipePayloadSync na fullRecipeToPayload.
6. Na succes: invalidate UI; optioneel versie-rij verwijderen of behouden (meestal behouden voor geschiedenis).

Geen aparte prompt; dit is puur client + SQLite.
Feature 8 — Weekplanner (Sonnet)
System prompt:
Je helpt met weekplanning voor maaltijden (alleen diner).
De gebruiker geeft aan voor welke dagen ze willen plannen,
en kan optioneel wensen meegeven.
Kies recepten uit hun collectie. Hergebruik ingrediënten slim
(bijv. als maandag paprika's gebruikt, plan dinsdag iets met paprika).
Houd rekening met "cooks_for_days" als de gebruiker aangeeft 
voor meerdere dagen te koken.

User message bevat:
- Lijst van beschikbare recepten (id, title, category, tags, 
  key ingredients)
- Dagen waarvoor gepland moet worden
- Wensen-tekst van de gebruiker
- Eventuele "wil ik proberen"-recepten als suggesties

Output: array van { date, recipe_id, servings, cooks_for_days }
Boodschappenlijst (client-side aggregatie)
Geen AI nodig — puur client-side:

1. Voor elke geplande maaltijd: 
   ingredients × (plan.servings / recipe.base_servings)
2. Groepeer op genormaliseerde (name + unit)
3. Tel amounts op
4. Sorteer op shopping_category
5. "naar smaak" items: toon zonder hoeveelheid, niet optellen

Edge cases:
- "2 el olijfolie" + "3 el olijfolie" → "5 el olijfolie"
- "200g kipfilet" + "300g kipfilet" → "500g kipfilet"  
- "1 ui" + "2 uien" → "3 ui(en)" — normaliseer meervoud
Error handling & edge cases
Claude API-fouten: Wrap elke API-call in try/catch. Bij netwerk-fouten of 5xx: toon "Geen verbinding met AI — probeer opnieuw". Bij 4xx (rate limit, invalid key): toon specifieke melding. Bewaar het user-bericht zodat ze het kunnen her-versturen.
Onverwachte JSON-responses: Na elke Claude-response, valideer tegen het verwachte schema. Als de JSON invalid is of verplichte velden mist: toon een fallback-UI met de ruwe response en een "opnieuw proberen"-knop. Log de fout lokaal voor debugging.
URL-extractie fallbacks: Sommige sites blokkeren scraping. Als de fetch faalt: toon een melding dat de site niet ondersteund wordt, en bied aan om het recept handmatig in te voeren. Alternatief: laat de gebruiker HTML plakken.
Offline-modus: Check netwerkstatus bij elke AI-actie. Als offline: disable AI-knoppen visueel (greyed out + tooltip). Alle niet-AI-functies (receptweergave, checkboxes, timers, schaling, zoeken, receptlijsten, boodschappenlijst) werken volledig offline.
